## 1. 动机:为什么换 Lucide

### 1.1 emoji 的问题

v0.4.16 之前全站用 emoji 图标(📌 ✅ 📊 等),三个硬伤:
- **跨平台不一致**:Windows / macOS / Linux 各自渲染,同一 emoji 在不同系统画风差异巨大
- **深色背景对比度差**:彩色 emoji 在深紫黑玻璃背景上要么太跳要么看不清
- **无统一设计语言**:emoji 来自不同厂商,线条粗细 / 风格 / 视觉权重不统一

### 1.2 为什么选 Lucide

- 线条图标(1.8px stroke),统一设计语言
- 开源(ISC),可商用
- 纯 SVG,无字体加载,渲染快
- 支持 `data-lucide="kebab-name"` 声明式用法,`createIcons()` 自动转 svg
- 体积可控(完整 bundle 585KB,自托管可接受)

### 1.3 离线优先的硬约束

本项目是本地优先的知识工作台,**必须在离线状态下完整渲染**。所以 Lucide 必须**本地 vendored**,
绝不依赖外部 CDN。这个约束写进 AGENTS.md Hard Rules。

## 2. v0.4.16 事故与教训

### 2.1 事故经过

首次 vendoring Lucide 时,下载的 bundle 被截断 / 残缺,静默缺失大部分图标。
- **表现**:`alarm-clock` 等图标显示成文字「alarm-clock」而非图标
- **隐蔽性**:bundle 能正常加载(无 404 / 无 JS 报错),只是内容不全,`createIcons()` 找不到
  对应图标就保留原 `<i>` 文本
- **调试耗时**:数小时,因为「能加载」误导排查方向

### 2.2 根因

下载后**没有验证文件内容**,直接提交了残缺 bundle。

### 2.3 沉淀的规范

AGENTS.md「Vendoring JS 库」:
> 下载任何 vendored JS 后,**提交前先验证内容**:检查文件大小是否接近完整 bundle,
> 并 grep 几个你会用到的具体符号名。

并要求下载 URL 钉死具体版本(`@0.460.0`,不要 `@latest`),保证可复现。

## 3. refreshIcons 双机制设计

### 3.1 为什么需要两条机制

静态 HTML 里的 `<i data-lucide>` 在首屏 `createIcons()` 时就转好了。但动态渲染的
列表 / 卡片(JS 插入的 HTML)需要重新扫描转换。问题是:哪些场景该刷新、谁负责刷新?

### 3.2 主次分明的设计

**主机制 = 显式调用**(`window.refreshIcons`):
- 已知的动态渲染流程(列表加载、卡片插入后)**主动**调用
- 优点:可控、即时、可预期
- 这是**首选**,代码里明确调用,不省略

**兜底机制 = MutationObserver**:
- 全局监听 DOM 变化,下一帧(rAF 防抖)刷新
- 优点:捕获不可控的第三方 DOM 改动
- 缺点:有一帧延迟、全局开销
- **只用于兜底**,不得替代显式调用

### 3.3 为什么不按容器范围渲染

理想做法是只处理新插入的容器,不扫整个 document。但调研发现:
- lucide@0.460 的 `createIcons()` 内部总是全局 `querySelectorAll('[data-lucide]')`
- `replaceElement` 未导出,无法 hack 成按容器渲染

权衡:Lucide 替换是幂等的(已转图标失去 `data-lucide`,下次扫描自动跳过),
全局扫描实际开销很小。**结论**:不为容器范围去 fork Lucide,走全局调用即可。

## 4. cat-meta.js 单一数据源设计

### 4.1 问题:4 份重复定义

v0.4.16 之前,类别元数据散落在 calendar / events / tasks / workspace 四个页面各自定义。
v0.4.16 事故排查时发现:「会议」类别在不同页面配色不一致(一处 `#3b82f6` 错值,
一处 `#2563eb` 正确值)。这正是重复定义的必然结果。

### 4.2 决策:单一数据源

抽取 `cat-meta.js`,所有页面只读取、不重定义。加新类别只改这一处。

### 4.3 为什么两套类别独立维护

事件类别(`KB_CATEGORIES`)和任务类别(`KB_TASK_CATEGORIES`)是**不同业务域**:
- 事件:会议 / 财报 / 截止日期 / 发布 / 比赛(todolist 是日历特有)
- 任务:开发 / 科研 / 个人 / 金融 / 工作

合并会导致「开发」这种任务类别出现在事件下拉里(语义不通)。且两套的「其他」配色
**故意不同**(事件橙 vs 任务紫),视觉上区分两个业务域有益。

### 4.4 防裸拼函数的关键作用

`catIcon(cat)` 返回 `<i data-lucide="...">` 标签字符串,而非裸 iconName。
原因:如果模板里写 `'<span>' + iconName + '</span>'`,Lucide 不会扫描 `<span>`,
图标名就显示成文字(v0.4.16 事故的同款症状)。包在 `data-lucide` 里才能被 `createIcons()` 识别。

### 4.5 自定义类别的稳定配色

用户可自定义 category(后端不校验白名单)。`catColor` 对未知类别用**字符串 hash 取稳定色**
(同一类别名每次算出同一颜色),保证自定义类别配色不会每次刷新变。

## 5. AGENTS.md 规范重写

v0.4.16 事故 + cat-meta 抽取暴露了「规范缺失」的问题。重写 AGENTS.md,新增 / 强化:
- **Data Ownership**:单数据源原则 + 现状表 + 已知双写风险清单(改这些字段时务必两处一起改)
- **前端 / 图标规范**:主次机制、容器范围说明、Vendoring 验证
- **Shared Category Metadata**:禁止页面重定义类别
- **UI Debugging Order**:六步排查法(Node ≠ 浏览器,静态分析不可靠)
- **Frontend Modification Boundaries**:局部修改只动指定模块,不重新设计整页

## 6. 深色对比度修复(v0.4.18)

### 6.1 问题

Ardot 深紫黑玻璃调色板的表面透明度(`--c-surface` 5%)太低,卡片 / badge 在 `#030014`
近黑底上几乎隐形 —— 看起来像纯黑底,玻璃质感变成了「什么都没有」。

### 6.2 决策:微提亮,不重做

不换调色板(玻璃质感是设计目标),只微提透明度:5% → 8%、3.5% → 5.5%。
元素重新可见,玻璃质感保留。文字同步提亮(`#ececff` / `#9aa0c7`)。
